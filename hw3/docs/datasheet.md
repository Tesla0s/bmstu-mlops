# Паспорт датасета: классификация обращений GitHub

## Назначение и формат

Модель читает заголовок и описание англоязычного обращения и возвращает
JSON с полем `category`: `bug` — сообщение о неправильной работе,
`feature_request` — предложение возможности или улучшения,
`question` — просьба объяснить использование программы или среды разработки.
Это задача предварительной сортировки обращений, а не установления технической
причины неисправности.

Одна строка JSONL — один JSON-объект с `id`, `topic` и тремя сообщениями
`system → user → assistant`. Пример ответа: `{"category": "bug"}`.
Схема не разрешает лишние поля, пустые значения или переставленные роли.
Ссылки, даты, метки источника и категория в служебной записи не входят в сообщение
пользователя. Их место — отдельный файл метаданных под управлением DVC.

## Источник и условия использования

Собственная выгрузка публичных обращений:
[microsoft/vscode](https://github.com/microsoft/vscode/issues) и
[pandas-dev/pandas](https://github.com/pandas-dev/pandas/issues).
Получение через [GitHub Search API](https://docs.github.com/en/rest/search/search#search-issues-and-pull-requests).
Фиксация выгрузки — **17 сентября 2026 года**; даты создания обращений — 2019–2025.
Выбирались закрытые обращения с целевыми метками. На сочетание проекта и метки
скачивалось до 1000 последних результатов внутри заданного периода.
Для VS Code дополнительно взят срез вопросов за 2019–2023 годы.
В описании исходника сохранены все семь запросов, их объёмы и SHA-256 файла.

| Проект | bug | feature_request | question |
|---|---|---|---|
| VS Code | bug | feature-request | *question |
| pandas | Bug | Enhancement | Usage Question |

VS Code указывает [MIT](licenses/vscode-MIT.txt), pandas —
[BSD-3-Clause](licenses/pandas-BSD-3-Clause.txt).
[Условия GitHub, раздел D.6](https://docs.github.com/en/site-policy/github-terms/github-terms-of-service#6-contributions-under-repository-license)
описывают лицензирование вкладов в репозиторий с указанной лицензией.
Права первоначальных авторов сохраняются; дополнительные условия заимствованных
фрагментов не отменяются. Новая единая лицензия на всю смесь пользовательских
текстов не объявляется.

Назначение выгрузки — открытая учебная исследовательская работа.
[Правила GitHub, раздел 7](https://docs.github.com/en/site-policy/acceptable-use-policies/github-acceptable-use-policies#7-information-usage-restrictions)
разрешают исследовательское использование публичной неперсональной информации
при открытой публикации результатов. Контактные данные маскируются до обучения.
В Git опубликованы код, конфигурация, проверки и отчёты; JSONL и исходные тексты
хранятся в локальном DVC-хранилище. Ссылки на исходные обращения позволяют
проверить происхождение записей.

Применены проверки меток и языка, удаление служебных форм,
содержательная проверка выборки и балансировка категорий внутри каждого проекта.

Причины исключения учитываются последовательно: каждая запись попадает только
в одну строку таблицы. Счётчики удалённых элементов форм находятся
в [metrics/collect.json](../metrics/collect.json); один текст может содержать
несколько удалённых элементов, поэтому эти счётчики нельзя складывать
как количество исключённых обращений.

Убираются типовые префиксы BUG/ENH/QST/FEAT, строки выбора типа, подсказки
формы, флажки-подтверждения, перечни установленных пакетов и диагностические
сводки редактора. Значимые примеры кода и параметры функциональных URL сохраняются.
Изображения заменяются маркером; их содержание модель не получает.

Категория question отбирается консервативно: в тексте вне кода и URL
должен быть вопросительный знак либо явная просьба о помощи/объяснении.
Это осознанное сужение задачи, **а не доказательство правильности метки**.
Вопросы, сформулированные косвенно, могут потеряться.
Остальные категории ограничены по числу примеров так, чтобы название проекта
само по себе не предсказывало ответ. До очистки в v2 на каждый класс приходится
376 обращений VS Code и 275 обращений pandas.

## Проверка содержания

Проверены **120 описаний** с помощью Codex: сначала 90 (по 15 на каждое
сочетание проекта и категории), затем ещё 30 вопросов после уточнения правил.
Список идентификаторов, решения и причины сохранены в
[журнале проверки](../reviews/label_audit.json).
Первый просмотр выявил 22 спорные или неполные записи, повторный — ещё 4.
Из 26 исключённых решений 24 дают отдельный счётчик collect;
ещё 2 уже исключаются более ранней проверкой заявленного типа.

Проверка использована при подготовке данных **до окончательной фиксации частей**.
Это проверка описаний с помощью ИИ, не независимая человеческая разметка
и не измерение точности меток на всём наборе. Модель классификации не запускалась.

## Очистка и персональные данные

Порядок: проверка схемы → длина входа 30–4000 символов и непустой ответ
→ маскирование → точные повторы → близкие повторы.
Слишком длинные сообщения исключаются целиком, без обрезки середины кода.
Повторяющиеся идентификаторы и повреждённая строка останавливают обработку;
для ошибки JSONL указывается номер строки.

Маскируются контакты, даты рождения с явным контекстом, имена в типовых подписях,
имена пользователей в домашних путях, упоминания вне кода,
учётные данные в строках подключения и распознаваемые секреты.
Обычные даты и версии библиотек сохраняются.
В v2 изменена **141 запись**; число замен по типам:

## Длины, категории и разнообразие

| Длина user, символов | p10 | p50 | p90 | Минимум | Максимум |
|---|---:|---:|---:|---:|---:|
| v2 | 216 | 636 | 1842 | 56 | 3989 |

Отношение p90/p10 длин входов — 8.53.
Словарь содержит 9735 различных английских слов из трёх и более букв.
Все нормализованные входы уникальны.

| Категория | Всего | train | val | test |
|---|---:|---:|---:|---:|
| `bug` | 615 | 431 | 91 | 93 |
| `feature_request` | 627 | 439 | 94 | 94 |
| `question` | 636 | 445 | 96 | 95 |

Есть **5** равнозначных системных инструкций; каждая встречается во всех классах.
Инструкция выбирается по идентификатору, без использования метки.

Два исходных порога изменены по разрешённому в задании исключению для классификации:

- Доля самой частой длины ответа: 0,25 → **0,45**.
  Три JSON-метки имеют длины 19, 24 и 31; в сбалансированном наборе
  доля каждой длины неизбежно около трети.
- Доля дословно повторяющихся ответов: 0,30 → **1,00**.
  Повторение названий трёх классов является целевым поведением,
  поэтому этот показатель здесь не доказывает вырожденность.

Остальные исходные ограничения сохранены, включая p90/p10 ответов ≥ 1,6
(фактически 1.63).
Взамен добавлены обязательные три класса, корректность JSON-ответа, доля каждого
класса 20–45%, пять распределённых инструкций (не менее трёх в каждом классе),
разброс длин входов ≥ 2, словарь ≥ 1000 и отсутствие повторов входного текста.
Доля одной инструкции ограничена 30%.
Набор с одним классом или одной инструкцией по-прежнему отклоняется.

## Группы, разделение и отсутствие пересечений

`topic` обозначает **семейство связанных обращений**, а не один из трёх классов.
Группы строятся на полном подходящем исходнике до выбора v1/v2:
по содержательным одинаковым заголовкам внутри проекта, сходству заголовков
из ≥ 5 слов (Жаккар ≥ 0,8) и явным ссылкам на дубликаты.
При удалении повторов их группы объединяются.
Большинство обращений независимы, поэтому большинство групп одноэлементные.
В v2 **1876 групп**, крупнейшая содержит 2 обращения.
Разнообразие не выводится только из числа этих групп: отдельно проверяются
входные тексты, длины, словарь и категории.

Связанные группы целиком распределяются по train/val/test.
Внутри каждого сочетания проекта и категории группы упорядочены по дате
самого нового обращения; целевые доли — 70/15/15.
Это уточнение первоначального плана: оно сохраняет все классы в каждой части
при разных календарных распределениях источников.
**Единой общей временной границы нет**: диапазоны дат разных категорий
пересекаются. Такой тест не является строгим прогнозом на будущий период.

Близость входов проверяется по множествам шинглов из четырёх слов.
Вместо вероятностного решения MinHash/LSH используется точный поиск
с предварительным отбором кандидатов и реальным коэффициентом Жаккара.
Порог одинаков при очистке и проверке частей: **0,85**.
Корректность предварительного отбора проверена сравнением с полным перебором
в дополнительных тестах. Это лексическая проверка; все смысловые перефразы
она не обязана обнаруживать.

Отдельная стадия `contamination` проверяет train/val, train/test и val/test:
по идентификаторам, нормализованным входам, группам и близким парам.
**Все 12 чисел равны нулю.** Дополнительно проверяется, что каждая очищенная
запись попала ровно в одну часть. Ненулевое пересечение останавливает обработку.

## Версии, восстановление и ограничения

Исходник и все промежуточные JSONL находятся под DVC; в Git — только
указатели, код, конфигурация, агрегированные метрики и отчёты.
Зависимости закреплены в `uv.lock`.
Выбор версии: `make v1` / `make v2`.
Сравнение Git-меток: `make diff`.
Полные измерения — [reports/versions.json](../reports/versions.json).

Набор отражает два проекта, закрытые обращения и ограниченные выборки
внутри 2019–2025 годов. Метки и отредактированные тексты соответствуют моменту
выгрузки, а не обязательно моменту создания обращения.
Категории искусственно сбалансированы; естественная частота обращений другая.
Фильтрация вопросов упрощает их языковую форму; ошибки меток полностью не исключены.
Распределение дат и тем отличается между категориями.
Изображения, обсуждения и сведения, доступные только по ссылкам, не анализируются.
Не проверялось, входили ли публичные обращения в предобучение будущей базовой модели.

Изначальный ориентир около 3000 записей уменьшен до 1878 ради более однозначных
категорий. Обе версии превышают обязательные 1000.
Длины пока измерены в символах; токенизация и выбор длины контекста относятся к ДЗ 4.
Обучение и качество будущей модели в этой работе не измерялись.

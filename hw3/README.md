## Запуск

Нужны Git, Python 3.12 и [uv](https://docs.astral.sh/uv/getting-started/installation/).
Все команды ниже выполняются из папки `hw3`.

~~~bash
uv sync --frozen
uv run dvc pull
make verify
make diff
~~~

`make verify` пересчитывает необходимые стадии, запускает 13 дополнительных
тестов, проверяет оформление кода и выполняет все восемь проверок преподавателя.

Данные намеренно отсутствуют в Git. Для точного восстановления нужен локальный
каталог DVC-хранилища, созданный при выполнении работы. При переносе проекта
задайте полный путь **локально**: это также обеспечивает правильный адрес
при переключении между рабочими копиями и Git-метками. Затем выполните pull:

~~~bash
uv run dvc remote modify --local local url /полный/путь/к/dvc_remote
uv run dvc pull
~~~

Одного клонирования Git недостаточно для получения датасета. Если хранилища нет,
`make fetch` создаёт новую выгрузку через GitHub API, а `make repro` обрабатывает её.
Метки и тексты на GitHub могут измениться, поэтому новая выгрузка не обещает
побайтового совпадения с зафиксированной. Перезапись существующего источника
сборщик запрещает. Вход через `gh auth login` необязателен, но повышает лимит запросов;
токены в файлы проекта не записываются.

## Команды

| Команда | Действие |
|---|---|
| `make repro` | `collect → clean → diversity → split → contamination` |
| `make v1` / `make v2` | Переключить версию и пересчитать зависимости |
| `make diff` | Реальная разница метрик очистки между Git-метками |
| `make dag` | Показать зависимости стадий |
| `make check` | Неизменённые восемь проверок преподавателя |
| `make test` | 13 дополнительных проверок алгоритмов и очистки |
| `make lint` | Проверка ошибок и оформления Python-кода |
| `make contamination` | Проверить все пары train/val/test отдельно |
| `make push-data` | Сохранить данные выбранной версии в локальном хранилище |

Данные каждой версии сохраняются отдельно:

~~~bash
make v1
make push-data
make v2
make push-data
~~~

После переключения на Git-метку команда `uv run dvc pull` восстанавливает
именно её файлы. Перед сменой метки сохраните локальные изменения.

Исходная выгрузка и её описание хранятся в `data/source` и учитываются
в `source.dvc`. Результаты стадий перечислены в `dvc.yaml` и `dvc.lock`.
Служебные метки, ссылки и даты сохраняются отдельно в `data/metadata.jsonl`:
модель их не получает.

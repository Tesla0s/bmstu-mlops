# ДЗ 1 — окружение, генерация и измерение производительности

Проект загружает модель из `params.yaml`, отвечает на заданный там вопрос и
отдельно измеряет время загрузки, скорость генерации и пиковую память процесса.
Общий код генерации используется и для вывода ответа, и для измерений.

## Быстрый запуск

Все команды этой работы выполняются из папки `hw1`:

```bash
cd hw1
```

Нужны macOS или Linux, `make`, доступ к интернету для первого скачивания и `uv`.
Python 3.12.14 устанавливается автоматически. Окружение, инструменты и кэш моделей
хранятся внутри проекта и исключены из Git.

Если `uv` ещё не установлен, из папки `hw1`:

```bash
curl -LsSf https://astral.sh/uv/install.sh | env UV_UNMANAGED_INSTALL="$PWD/.tools/bin" sh
```

Затем:

```bash
make install
make generate
HF_HUB_OFFLINE=1 make bench
make test
make check
HF_HUB_OFFLINE=1 make verify
```

`make install` и команды запуска используют `uv.lock` с проверкой его актуальности
(`--locked`). Версии прямых зависимостей закреплены в `pyproject.toml`.
Для прямого вызова локального `uv`: `.tools/bin/uv --version`.

Первая генерация скачивает файлы модели в `.cache/huggingface/`.
Измерение с `HF_HUB_OFFLINE=1` выполняется после скачивания и не включает
обращения к сети. `make check` при первом запуске скачивает также небольшую
модель для проверки подмены конфигурации. После этого проверку можно запускать
как `HF_HUB_OFFLINE=1 make check`.

## Настройки компьютера

В сохранённой конфигурации выбрано устройство `mps` — графический процессор Apple.
На другом компьютере измените `model.device` в `params.yaml`:

- `auto`: выбрать доступное устройство в порядке NVIDIA → Apple → процессор;
- `cuda`: использовать графический процессор NVIDIA;
- `mps`: использовать графический процессор Apple;
- `cpu`: использовать центральный процессор.

Явно выбранное недоступное устройство вызывает понятную ошибку.
Формат вычислений меняется через `model.dtype`; для сравнения на центральном
процессоре можно выбрать `float32`. Название модели меняется исключительно в
`params.yaml`; исходный код редактировать не требуется.

При `temperature: 0.0` следующий токен выбирается без случайного сэмплирования.
`seed` применяется к Python, NumPy и PyTorch при загрузке модели.
Одинаковый вывод проверен в отдельных процессах на зафиксированном окружении.
Совпадение текста между разными устройствами и версиями библиотек не обещается.

## Команды и результаты

| Команда | Результат |
|---|---|
| `make install` | Воспроизводимое окружение из `uv.lock` |
| `make generate` | Ответ модели и фактическое число новых токенов |
| `make bench` | Результат в терминале и `docs/bench.json` |
| `make test` | Проверки разделения таймеров и обязательного прогрева |
| `make check` | Исходные пять проверок преподавателя |
| `make verify` | Два успешных запуска, одинаковый ответ и проверка чисел в отчёте |
| `make clean` | Удаление временных файлов проверки |

Основной отчёт: [docs/hardware.md](docs/hardware.md).
Исходные результаты измерений и журналы проверок находятся в `docs/`.
Повторный `make bench` перезаписывает `docs/bench.json`.

## Как устроено измерение

1. Таймер загрузки охватывает токенизатор, модель и ожидание готовности устройства.
   Импорт библиотек и запуск интерпретатора происходят до этого таймера.
2. Вопрос оформляется шаблоном модели, преобразуется в токены и переносится на
   устройство до измерения скорости.
3. Выполняются предварительные прогоны из `bench.warmup_runs`; их время исключено.
4. Каждый измеряемый запуск имеет собственный таймер. Перед стартом и после
   генерации программа дожидается завершения вычислений устройства.
5. Скорость запуска равна числу действительно созданных токенов, делённому на
   его время. Итог — медиана скоростей запусков.
6. Ответ преобразуется в текст после измерения. Пиковая RSS берётся через
   `resource.getrusage` и описывает максимум памяти процесса к моменту чтения,
   включая загрузку и прогрев. Единицы в поле `peak_rss_mb` — МиБ (2²⁰ байт).

Время генерации включает обработку входных токенов самой моделью и последовательное
создание ответа. Это не отдельный замер скорости выдачи токенов после первого токена.
RSS не следует трактовать как полное потребление памяти графическим процессором.
Ожидание окончания вычислений реализовано согласно [документации PyTorch](https://docs.pytorch.org/docs/2.8/generated/torch.mps.synchronize.html).

## Структура

```text
src/
  config.py       чтение и проверка параметров
  model.py        загрузка, шаблон диалога, общая генерация
  generate.py     вывод ответа
  bench.py        измерения и сохранение результата
tests/
  check.sh        неизменённая проверка преподавателя
  test_bench.py   дополнительные проверки измерений
  verify_runtime.py  проверка реальных запусков и результатов
docs/             отчёт, исходные результаты и журналы
data/             место для данных последующих ДЗ
conf/             место для конфигураций последующих ДЗ
params.yaml       параметры этой работы
pyproject.toml    версии прямых зависимостей
uv.lock           точные версии всех зависимостей
.python-version   версия Python
Makefile          команды проекта
```

По таблице из лекции 1 компьютер относится к профилю «Mac Apple Silicon,
16 ГБ+». Выбор общей базовой модели курса обоснован в отчёте.
Согласование темы данных для будущего дообучения пока остаётся открытым.

Лекция 1 предусматривает один репозиторий на весь семестр: следующие ДЗ
развивают этот проект, а результат каждой работы сохраняется коммитом.

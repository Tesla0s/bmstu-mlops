Токены — фрагменты текста, с которыми работает модель. Токенизатор преобразует

| Температура генерации | 0.0 |
| Начальное состояние генераторов случайности (`seed`) | 42 |
| Режим рассуждений | Выключен, `enable_thinking: false` |
| Предварительные прогоны | 1 |
| Измеряемые прогоны | 3 |
| Доступ к сети во время измерения | Отключён для загрузчика моделей: `HF_HUB_OFFLINE=1` |

Код версии файлов модели: `c1899de289a04d12100db370d81485cdf75e47ca`.
Он записан в результате измерения. Загрузчик принимает имя из конфигурации,
поэтому при новом скачивании следует учитывать возможное обновление модели
на сервере; библиотечный `uv.lock` не фиксирует веса модели.

Шаблон диалога берётся у самой модели; специальные токены при последующем
преобразовании вопроса в числа повторно не добавляются. Режим рассуждений
выключается параметром шаблона, как описано в
[официальной карточке модели](https://huggingface.co/Qwen/Qwen3-0.6B).
При температуре 0 программа выбирает следующий токен без случайного сэмплирования
и сбрасывает унаследованные параметры случайного выбора к нейтральным значениям.

## 4. Методика измерений

**Время загрузки.** Таймер запускается непосредственно перед загрузкой
токенизатора и модели и останавливается после ожидания готовности устройства.
Запуск Python и импорт библиотек в этот показатель не входят.
Модель предварительно скачана; во время замера загрузчик работает без сети.
Таким образом, измерена подготовка модели из локального кэша,
а не первоначальное скачивание и не полный запуск команды.

**Скорость генерации.** Вопрос подготавливается и переносится на устройство
заранее. Затем выполняется один прогрев, исключённый из результата.
У каждого из трёх последующих запусков свой таймер.
Перед стартом и после генерации программа дожидается вычислений устройства
через `synchronize`; назначение этой операции описано в
[документации PyTorch](https://docs.pytorch.org/docs/2.8/generated/torch.mps.synchronize.html).

Для каждого запуска:

```text
скорость = фактическое число новых токенов / время этого запуска
итоговая скорость = медиана трёх скоростей
```

Измерение включает обработку входа самой моделью и создание новых токенов.
Подготовка текста, преобразование его в токены, загрузка модели,
прогрев и перевод ответа обратно в текст в измерение скорости не входят.
Лимит 200 — верхняя граница: делить на время всегда 200 было бы ошибкой,
поскольку здесь модель завершает ответ после 71 токена.
Созданные служебные токены учитываются в числе токенов, но скрыты в тексте.

**Пиковая память.** Используется `resource.getrusage(resource.RUSAGE_SELF).ru_maxrss`:
максимальная резидентная память процесса (RSS — Resident Set Size) к моменту
чтения показателя, включая загрузку, прогрев и измерения. Это максимум,
который отслеживает операционная система, а не однократный снимок текущей памяти.
На macOS исходные байты переводятся в МиБ делением на 2²⁰; на Linux исходное
значение в КиБ делится на 1024. Семантика максимума описана в
[документации Python](https://docs.python.org/3.12/library/resource.html).

RSS не равна всему объёму памяти, занятой моделью и графическим процессором.
В частности, число ниже теоретического размера параметров не означает,
что все параметры занимают только столько памяти.
Отдельный пик памяти графического процессора в этой работе не измерялся.

## 7. Найденные дефекты и исправления

### 7.1. Название модели было прописано в трёх местах Python-кода

**Где:** исходные `src/model.py`, `src/generate.py` и `src/bench.py`.

**В чём ошибка:** загрузчик игнорировал выбранную модель в конфигурации;
вывод генерации и отчёт тоже содержали постоянную строку.

**Как проявлялась:** изменение `model.name` не меняло загружаемую модель,
а сообщения могли сообщать неверное название.

**Исправление:** все три места читают `params["model"]["name"]`.
Общая функция загрузки используется и при генерации, и при измерениях.

**Проверка:** в исходном коде нет названий реальных моделей. Самопроверка
преподавателя временно меняет файл конфигурации и проверяет имя загруженной модели.
Дополнительно выполнена генерация маленькой моделью; исходный файл параметров
после проверки сохранён без изменений.

### 7.2. Зависимости не были зафиксированы

**Где:** исходный `pyproject.toml`; файла `uv.lock` не было.

**В чём ошибка:** перечислялись только названия библиотек; не фиксировались
ни прямые, ни косвенные зависимости.

**Как проявлялась:** установки в разное время могли получать разные версии
и поведение. Это следует из исходного описания зависимостей;
исторические установки на других компьютерах не воспроизводились.

**Исправление:** закреплены точные версии пяти прямых зависимостей,
создан `uv.lock`, версия Python закреплена на 3.12.14.
Команды установки и запуска проверяют актуальность файла зависимостей.

**Проверка:** установка завершилась успешно, `uv pip check` не нашёл конфликтов,
соответствующий пункт исходной самопроверки пройден.

### 7.3. Измерение скорости включало загрузку и предшествующие запуски

**Где:** исходный `src/bench.py`.

**В чём ошибка:** один таймер запускался до загрузки модели и использовался
во всех измерениях; прогрева не было; `load_time` записывался как `0.0`.

**Как проявлялась:** скорость включала стоимость загрузки, а во втором и третьем
результате — ещё и время предыдущих генераций. Даже при одинаковой реальной
скорости получались искусственно заниженные и несопоставимые числа.

**Исправление:** отдельный таймер загрузки, обязательный прогрев,
отдельный таймер каждого измеряемого запуска, ожидание графического процессора.
Подготовка вопроса и декодирование исключены из скорости.
Итог вычисляется как медиана скоростей по фактическому числу новых токенов.

**Проверка:** дополнительный тест имитирует долгую загрузку, дорогой прогрев,
разные длины ответов и незавершённую работу ускорителя.
Он проверяет точные длительности и медиану.
Другой тест проверяет отказ от измерения без прогрева.
Арифметика реального [bench.json](bench.json) также проверена.

### 7.4. Генерация не была настроена на воспроизводимость

**Где:** исходные `params.yaml` и точки запуска.

**В чём ошибка:** стояла температура 0.7. Функция фиксации случайности
уже существовала, но не вызывалась; число 42 в файле параметров само по себе
не меняло состояние генераторов.

**Как проявлялась:** случайный выбор токенов без применения `seed`
мог давать разный ответ при одинаковом вопросе.

**Исправление:** температура установлена в 0.0.
Общий загрузчик применяет `seed` к Python, NumPy и PyTorch.
Режим оценки модели и режим вычислений без градиентов сохранены.

**Проверка:** исходная проверка сравнения выводов пройдена.
Дополнительно проверены коды завершения двух процессов,
непустой ответ и полное побайтовое совпадение.

## 9. Команды воспроизведения

Из папки `hw1`, после установки `uv` по инструкции в [README](../README.md):

```bash
make install
make generate
HF_HUB_OFFLINE=1 make bench
make test
make check
HF_HUB_OFFLINE=1 make verify
```

Первый `make generate` скачивает основную модель; первый `make check` также
скачивает проверочную. Последующие запуски проверок можно выполнять с
`HF_HUB_OFFLINE=1`. Повторный `make bench` перезапишет исходные результаты,
поэтому для сохранения текущего эксперимента они включены в Git вместе с отчётом.

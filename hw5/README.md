# ДЗ5 — LoRA для классификации обращений GitHub

В работе обучаются небольшие добавки к замороженной Qwen3-0.6B: модель читает
описание обращения и выдаёт JSON с категорией bug, feature_request или question.
Сравниваются добавки на всех 28 слоях и только на слоях 14–27.

Вход — неизменённые тензоры ДЗ4: 1315 обучающих и 281 проверочный пример.
Ревизия модели и шаблон совпадают с ДЗ4. Итоговая тестовая часть ДЗ3 не используется.

## Запуск в рабочей копии

Команды выполняются из папки hw5, с Python 3.12 и установленным uv.

    make install
    make pull-data
    make train
    make compare
    make test
    make lint
    make check
    make audit

make train использует DVC: актуальные результаты повторно не обучаются.
Чтобы заново выполнить оба опыта, используйте:

    uv run dvc repro --force train_all train_freeze curves report

При этом DVC удаляет прежние выходы пересчитываемых стадий; перед новым
экспериментом сохраните нужные версии через make push-data и Git.

Проверка преподавателя не изменена, её отпечаток: 06a02208c1f0.
Она проверяет готовые результаты и действительно выполняет два коротких
обучения по три шага. Видеозапись полного обучения не требуется.

## Данные и веса находятся отдельно от Git

В Git хранятся код, параметры, uv.lock, описание стадий DVC, график и отчёты.
Тензоры, адаптеры, JSON-метрики, окружение и кэши не коммитятся.

Хранилище DVC по умолчанию — соседняя папка hw5/workspace/dvc_remote.
После клонирования на другой компьютер нужен доступ к копии этого хранилища:

    uv run dvc remote modify --local local url /полный/путь/к/dvc_remote
    make pull-data

Сам Git-клон не содержит обученных адаптеров и данных. Если доступны только
готовые тензоры ДЗ4 в соседнем hw4, входы можно восстановить командой:

    uv run python -m scripts.prepare_inputs

## Базовая модель

Используется Qwen/Qwen3-0.6B, ревизия c1899de289a04d12100db370d81485cdf75e47ca.
На рабочей машине модель уже находится в кэше; make по умолчанию работает
без сети. В чистом окружении загрузите закреплённые файлы один раз:

    HF_HUB_OFFLINE=0 uv run python -m scripts.prepare_model

HF_HOME в Makefile указывает на .cache/huggingface. На рабочей машине это
ссылка на ранее заполненный кэш; при клонировании такая ссылка не нужна.
Проверка преподавателя загружает базу по имени модели; локальная ссылка refs/main
должна указывать на ту же закреплённую ревизию. Подробности в docs/validation.md.

## Настройки и вычисления

- Одна полная эпоха для каждого варианта; ограничение max_steps выключено.
- Микробатч 1, накопление по 8: обычный шаг использует 8 примеров.
  Последний шаг использует оставшиеся 3 примера, не теряя их.
- Ошибка и градиенты усредняются по обучаемым токенам всей группы.
  Промпт и позиции дополнения имеют метку −100.
- Проверка всех 281 примеров выполняется до первого шага, через каждые
  10 шагов и в конце.
- Базовые веса заморожены; обучаются только матрицы LoRA ранга 8.
  Вариант freeze14 создаёт их только в последних 14 слоях.
- На MPS используется eager-внимание: локальная проверка выявила NaN
  в sdpa с левым дополнением и bfloat16. Тот же выбор применяется при генерации.
- Модель читает весь контекст. Выходной слой считает вероятности только
  для позиций, у которых есть обучаемая метка следующего токена.
  Эквивалентность стандартной ошибки и градиентов проверяется тестами.

Поддержку выбора позиций описывает [документация Qwen3](https://huggingface.co/docs/transformers/model_doc/qwen3),
а выбор слоёв и состав адаптера — [документация PEFT](https://huggingface.co/docs/peft/en/package_reference/lora).

## Короткая проба

    uv run python -m src.train --variant all_layers --max-steps 5 --val-limit 16 --out /путь/к/новой/папке

Проба сохраняется отдельно от полных результатов. Код не перезаписывает
непустую папку адаптера при прямом запуске. Такие прогоны не выдаются за
полную эпоху и не используются для итоговых графиков.

В папке каждого адаптера сохраняются матрицы, конфигурация, токенизатор,
шаблон, полный файл параметров и контрольные суммы входов.
Базовые веса передаются отдельно или предварительно загружаются в кэш.

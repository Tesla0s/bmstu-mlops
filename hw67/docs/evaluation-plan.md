# Протокол, закреплённый до обучения и оценки

Тема: классификация обращений GitHub — bug / feature_request / question.
Источник — собственная версия hw3-v2, подготовленная и токенизированная в ДЗ 4.
База Qwen/Qwen3-0.6B закреплена ревизией c1899de289a04d12100db370d81485cdf75e47ca.
Обучение начинается заново от базы; адаптер ДЗ 5 не подмешивается.

Шесть конфигураций получают одинаковые 32 исходных train-примера и 8 val-примеров:
по возможности поровну из трёх классов, id сохранены в params.yaml.
Исходные train.pt/val.pt не изменены. Индекс утечек охватывает все 1315 train-примеров.
Бюджет — четыре шага, batch 1, accumulation 2, seed 42, оценка на шагах 0, 2, 4.
Ранг, скорость обучения и набор проекций меняются только по заранее заданной сетке.
Выбор минимального конечного val loss разрешён при val/base ≤ 1.0.
Test-набор не читается и в выборе не участвует.

Golden: 60 обращений из val ДЗ 4, по 20 на класс и 30 на репозиторий.
Они не пересекаются с восемью val-примерами текущего поиска.
Это отобранный набор разработки, уже принадлежавший val прошлого ДЗ, а не независимый
итоговый аудит. Обращения отбирались по полноте и содержательному соответствию метки,
до генерации обеих моделей. Неоднозначность ряда исходных GitHub-меток остаётся
ограничением. Для каждой строки сохранено отдельное обоснование, выполненное с помощью ИИ;
независимой экспертной разметкой этот разбор не называется.

Критические срезы — каждый из трёх классов: потеря ошибок опасна для маршрутизации,
предложения нельзя смешивать с обращениями в поддержку, а вопросы не должны
загружать очередь исправления дефектов. Дополнительные срезы — два репозитория и
длина текста ≤600 / >600 символов. Они пересекаются; их размеры нельзя складывать.
Протокол: одна system-инструкция, максимум 32 новых токена, отключённые рассуждения,
seed 42, жадная генерация, одинаковые устройство, точность и реализация внимания.
Модель получает только input и system, но не expected, slices и source.
Ответ принимается только как JSON с единственным строковым полем answer из choices.

Кандидат допускается в champion только при отсутствии ошибок генерации, общей
accuracy и доли правильного формата не ниже базы, отсутствии ухудшения каждого
критического среза и прохождении всех четырёх поведенческих строк:
формат, исходная формулировка, её перефраз, отказ от запроса кулинарного рецепта.
Пара перефразов связана с одним golden group_id и не увеличивает golden n.
Разрешённая регрессия равна нулю. Порог после оценки не меняется.
Baseline первоначально — исходная модель; автоматически обновлять его нельзя.

При отказе сохраняются кандидат и все сырые ответы, champion не назначается.
Отрицательная проверка портит только копию ответов.
Ограничение бюджета в четыре шага не позволяет делать вывод о наилучшем возможном
качестве LoRA; оно проверяет воспроизводимый путь учёта, выбора и допуска.

## Уточнение проверки полноты модели при повторном аудите

21 октября 2026 после исходной оценки обнаружен пробел отдельной quality_gate:
описание вида {"kind": "adapter"} принималось без версии. Реальная команда выпуска
уже сравнивала полное описание с реестром, но сама функция была недостаточно строгой.
Теперь она требует имя, точную ревизию базы либо числовую версию адаптера,
run_id и неизменяемый URI. Синтетический kind=fixture сохранён для исходных тестов
преподавателя; реальная обвязка требует совпадения с закреплённой моделью.

Это ужесточение проверки, а не изменение порога после просмотра ответов.
Данные, разметка, system-инструкция, генерация, критические срезы и нулевая
допустимая регрессия не меняются. Код будет зафиксирован до повторной генерации
обеих моделей; прежняя оценка останется в истории MLflow. Шесть обучений
повторять не нужно: их код, конфигурация и тензоры не менялись.
